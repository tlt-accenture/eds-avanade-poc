# Step 3: Block style variations and the Block styles plugin

**Status:** complete (2026-11-13)
**Design:** `docs/specs/004-block-style-plugin/spec.md`
**Plugin:** Document Authoring editor → Library → **Block styles**

## 1. The goal

Authors picked a block's look by typing an option into the block table header, e.g.
`columns-image-text (highlights)`. Nothing checked the word: a typo silently fell back to the default
look, and nothing showed what an option looked like before previewing the page.

Step 3 adds color and layout variations to three blocks, and a plugin in the Document Authoring (DA)
editor that shows each variation and inserts it, so nobody types option names.

**Why a plugin:** like choosing paint from swatches instead of typing a color code: you see it before
you commit, and you can't misspell it.

## 2. Decisions

| Decision | Choice |
|---|---|
| Which blocks | columns-image-text, hero-title-banner, cards-case-study (used on both templates) |
| Kinds of variation | Color themes and layouts |
| Where authors use it | The DA editor's Library panel |
| What a theme changes | The block's own surface: a rounded panel behind columns and banners, each card for cards |
| Gradient contrast | Darkened 20% so white body text passes accessibility (4.7:1 instead of 3.2:1) |
| Extra help (add-on) | The Block library add-on was enabled for the project |

## 3. The variations

Authors combine at most one layout and one theme, e.g. `cards-case-study (cols-2, dark)`.

| Block | Layouts | Themes (shared) |
|---|---|---|
| columns-image-text | image left, image right (whatever order the cells are in), stacked, highlights | dark, light grey, gradient |
| hero-title-banner | centered (default), split, left-aligned, with background image (text on the photo over a dark overlay) | same |
| cards-case-study | image cards (default), text cards, 2 per row, 4 per row | same |

- **One set of theme colors** lives in `styles/styles.css`, for blocks only. Each block decides what
  gets painted, and the site's color tokens flip automatically so text, links and buttons turn white
  on dark and gradient. One vocabulary for every block, like one light switch per room.
- **Client logos** sit on a small white tile on dark and gradient cards, because dark logos vanished
  on charcoal.
- **Existing pages are unchanged.** Every rule only applies when its option is set; the homepage and
  the service pages were measured against the live site after each change.

## 4. The samples page

`/library/block-styles` holds one real sample of each block: the homepage's "Industry fluency" row,
"The Avanade Story" banner and the client-story cards.

- It is **generated by the importer** (a small "library" import template), not written by hand, so it
  can be rebuilt the same way any time.
- The plugin uses it for its previews and for the rows it inserts, so sample text and images can be
  changed in DA without touching code.

## 5. The plugin

The **Block styles** panel (`tools/plugins/block-styles/`):

1. **Pickers** for block, layout and color theme. The choices come from each block's own option list,
   so a new option shows up automatically.
2. **A live preview** rendered by the block's real code, at desktop or phone width, scaled into the
   narrow panel. Like a dollhouse built at real proportions and shrunk: rooms stay where they belong.
3. **The block header** (e.g. `columns-image-text (image-right, dark)`) with a Copy button, for
   restyling a block already on the page.
4. **Insert block** puts the table with the sample content into the document and closes the panel.

**Limit:** a DA plugin can only insert content; it can't change a block already on a page. Authors
restyle an existing block by pasting the header text over its header.

## 6. Quality checks

- **Every option** was applied to real blocks and measured at desktop and phone widths: image side,
  panel colors, white text, cards per row, the background overlay.
- **Contrast:** dark 12.6:1, light grey 11.8:1, gradient 4.7–7.65:1 (all pass for body text).
- **The plugin:** every block, layout and theme; header text; preview sizing; keyboard use. Insert was
  tested with a stand-in for the editor's toolkit (it sends one table, then closes the panel).
- **Live check after merge:** homepage and Cloud render identically to before.
- **Page-speed check:** 100 (performance, accessibility and best practices 100; SEO 69 is normal for
  preview sites, which are hidden from search engines).

## 8. Update (2026-11-16): search and a DA-maintained style list

A "what if" exercise: a client has 30 style variations for one block and wants to type into a search
field to filter them. The current blocks have only a few variations, so this plugin is the test bed.

**Decisions:**

| Question | Choice | Why |
|---|---|---|
| One search bar, or one per group? | One bar for layouts and themes | Authors don't need to know which group a word belongs to, and one search can narrow both ("dark 2 per row") |
| Pill buttons or a list? | A scrolling list | 30 pills crowd a narrow panel; rows with a one-line description scan better and scroll |
| Who maintains the variations? | A DA spreadsheet | Authors add, rename, reorder and describe entries without a developer |

Like a store's website: one search box, results sorted under their departments, and a product list
the shop staff can update themselves.

**What changed:**

- **The sheet** `/library/block-style-options` has one row per variation: `block`, `group` (layout or
  theme), `class` (the option word in the block header), `label`, `keywords` and `description`. It
  started with the 19 existing variations and starting keywords (e.g. "photo" for "With background
  image").
- **Search** narrows each group by the words that mean something in it, and keeps the current pick in
  view (marked "current pick"). Per-group counts ("1 of 4"), an announced total, "No … match"
  messages, and Escape or × to clear.
- **The list** shows each choice as a row with its name and description; long groups scroll.
- **Safety:** rows with an unknown group or a malformed option word are skipped, so an authoring typo
  can't break the panel; without the sheet the panel falls back to the blocks' built-in lists.
- **The plugin's README** documents the sheet's columns.

**How authors change the list now:** edit `library/block-style-options` in DA, then preview it; the
panel shows the change the next time it opens. A brand-new style still needs a developer to add its
CSS first, because the sheet only controls the list (like rewriting the specials board: new names any
day, but a new dish still needs the kitchen).

**Checks:** search for single words, several words, keywords and no matches; clearing; a renamed entry
("Night mode", found by the new keyword "midnight"); a row with a typo (skipped); no sheet (built-in
list); and the live panel on `main` reading the real previewed sheet. Page-speed check 100.

## 9. Update (2026-11-17): the Avanade blocks in the block library

The DA editor's **Library → Blocks** panel still listed only Author Kit's starter blocks, and its
section styles were Author Kit's (container, center, adobe-red…). None of the 11 Avanade blocks built in
steps 1–3 were in it, so an author had to copy a block from another page or type its table by hand.

Now an author opens the library, clicks e.g. **Accordion (FAQ)**, and a ready-made block with sample
content drops into the page. Like a pantry of meal kits instead of a recipe book.

**Decisions:**

| Question | Choice | Why |
|---|---|---|
| How many entries? | One per layout | Showing every layout in every theme would add 30+ near-identical entries; themes are described in each entry and mixed in the Block styles panel |
| Author Kit's starter blocks | Hero, Card and Columns no longer listed; Table, Section Metadata and Metadata kept | Two different "heroes" would confuse authors; existing pages aren't affected |
| Section styles | Avanade's four: light-grey, pink-gradient, centered, grey-fade | The list should match what the site actually styles |

**What's in it: 14 blocks, 27 entries.**

| Library block | Entries |
|---|---|
| Accordion | Default, FAQ |
| Case study cards | Image cards, Text, 2 per row, 4 per row |
| Contact | Default |
| Homepage hero | Default, Card |
| Image and text columns | Image left, Image right, Stacked, Highlights |
| Jump links | Default |
| Metadata | Page title and description |
| News cards | Default |
| Promo carousel | Default |
| Quote carousel | Default |
| Section Metadata | Avanade section style and id |
| Stats cards | Default |
| Table | Kept from Author Kit |
| Title banner | Centered, Split, Left, With background image |

- **Where it lives in DA:** `docs/library/blocks.json` is the list, with the section style values in
  its `options` sheet. Each block has a sample page under `docs/library/blocks/`, one section per entry.
  The editor's settings already pointed at this list, so they didn't change.
- **Real content:** copied from the homepage and the Cloud page, cut down to 2–4 items. Every Services
  page has a single quote, so the quote carousel sample combines the Cloud, Security and Experiences
  quotes. The homepage has only three image case studies, so the "4 per row" sample repeats the first
  one.
- **Names and descriptions:** each entry has a `library-metadata` label with a plain name and a
  one-line description of what to put in it. A small block (`blocks/library-metadata`, PR #16) removes
  that label on rendered pages, so a previewed sample page shows no error boxes.
- **A fix along the way:** the old list's Metadata entry pointed at a page that didn't exist. It now
  has a sample (page title and description).
- **The old versions:** the replaced list and section style sample were saved before uploading, so they
  can be restored.

**Checks:** all 13 sample pages rendered with the real block code (no error boxes or script errors,
every image loads; the picture sits left, right or above as named; 2 and 4 per row show 2 and 4 cards;
the background banner has its photo and overlay). The copies in DA match the local ones exactly, and
all were previewed. Sample pages on `main`: 4 error boxes each before PR #16, none after. Page-speed
check 100.

**Author test in the editor (2026-11-17):** Library → Blocks lists the 14 blocks, and an inserted entry
arrives with its content and renders in its layout on preview. At first the editor still showed the old
list: Document Authoring doesn't tell browsers how long to keep the list, so a browser that read it
recently may reuse its saved copy for a few hours. Clearing the browser's cached files showed the new
list. If authors keep seeing an old list after a change, a version number on the list's address in the
site settings (`blocks.json?v=2`) makes every browser fetch it fresh.

## Not done in step 3

- **Restyling an existing block from the plugin** isn't possible with DA's plugin toolkit; the panel
  offers the header to copy instead.
- **A real author insert in the DA editor** is still to be tried by an author (it was verified with a
  stand-in for the editor's toolkit).
- **The `pink-gradient` section style** still uses the original, brighter gradient (3.2:1 for small
  white text at the orange end). Darkening it would change live pages and is a separate decision.
