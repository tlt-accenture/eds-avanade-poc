# Step 3: Block style variations and the Block styles plugin

**Status:** complete (2026-11-13)
**Design:** `docs/specs/004-block-style-plugin/spec.md`
**Plugin:** Document Authoring editor → Library → **Block styles**

## 1. The goal

Authors picked a block's look by typing an option into the block table header, e.g.
`columns-image-text (highlights)`. Nothing checked the word: a typo silently fell back to the default
look, and nothing showed what an option looked like before previewing the page.

Step 3 adds color and layout variations to three blocks, and a plugin in the Document Authoring (DA)
editor that shows each variation and inserts it, so nobody types option names.

**Why a plugin:** like choosing paint from swatches instead of typing a color code: you see it before
you commit, and you can't misspell it.

## 2. Decisions

| Decision | Choice |
|---|---|
| Which blocks | columns-image-text, hero-title-banner, cards-case-study (used on both templates) |
| Kinds of variation | Color themes and layouts |
| Where authors use it | The DA editor's Library panel |
| What a theme changes | The block's own surface: a rounded panel behind columns and banners, each card for cards |
| Gradient contrast | Darkened 20% so white body text passes accessibility (4.7:1 instead of 3.2:1) |
| Extra help (add-on) | The Block library add-on was enabled for the project |

## 3. The variations

Authors combine at most one layout and one theme, e.g. `cards-case-study (cols-2, dark)`.

| Block | Layouts | Themes (shared) |
|---|---|---|
| columns-image-text | image left, image right (whatever order the cells are in), stacked, highlights | dark, light grey, gradient |
| hero-title-banner | centered (default), split, left-aligned, with background image (text on the photo over a dark overlay) | same |
| cards-case-study | image cards (default), text cards, 2 per row, 4 per row | same |

- **One set of theme colors** lives in `styles/styles.css`, for blocks only. Each block decides what
  gets painted, and the site's color tokens flip automatically so text, links and buttons turn white
  on dark and gradient. One vocabulary for every block, like one light switch per room.
- **Client logos** sit on a small white tile on dark and gradient cards, because dark logos vanished
  on charcoal.
- **Existing pages are unchanged.** Every rule only applies when its option is set; the homepage and
  the service pages were measured against the live site after each change.

## 4. The samples page

`/library/block-styles` holds one real sample of each block: the homepage's "Industry fluency" row,
"The Avanade Story" banner and the client-story cards.

- It is **generated by the importer** (a small "library" import template), not written by hand, so it
  can be rebuilt the same way any time.
- The plugin uses it for its previews and for the rows it inserts, so sample text and images can be
  changed in DA without touching code.

## 5. The plugin

The **Block styles** panel (`tools/plugins/block-styles/`):

1. **Pickers** for block, layout and color theme. The choices come from each block's own option list,
   so a new option shows up automatically.
2. **A live preview** rendered by the block's real code, at desktop or phone width, scaled into the
   narrow panel. Like a dollhouse built at real proportions and shrunk: rooms stay where they belong.
3. **The block header** (e.g. `columns-image-text (image-right, dark)`) with a Copy button, for
   restyling a block already on the page.
4. **Insert block** puts the table with the sample content into the document and closes the panel.

**Limit:** a DA plugin can only insert content; it can't change a block already on a page. Authors
restyle an existing block by pasting the header text over its header.

## 6. Quality checks

- **Every option** was applied to real blocks and measured at desktop and phone widths: image side,
  panel colors, white text, cards per row, the background overlay.
- **Contrast:** dark 12.6:1, light grey 11.8:1, gradient 4.7–7.65:1 (all pass for body text).
- **The plugin:** every block, layout and theme; header text; preview sizing; keyboard use. Insert was
  tested with a stand-in for the editor's toolkit (it sends one table, then closes the panel).
- **Live check after merge:** homepage and Cloud render identically to before.
- **Page-speed check:** 100 (performance, accessibility and best practices 100; SEO 69 is normal for
  preview sites, which are hidden from search engines).

## Not done in step 3

- **Restyling an existing block from the plugin** isn't possible with DA's plugin toolkit; the panel
  offers the header to copy instead.
- **A real author insert in the DA editor** is still to be tried by an author (it was verified with a
  stand-in for the editor's toolkit).
- **The `pink-gradient` section style** still uses the original, brighter gradient (3.2:1 for small
  white text at the orange end). Darkening it would change live pages and is a separate decision.
